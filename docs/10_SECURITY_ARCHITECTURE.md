## 1. Threat Modeling & Security Posture

As an evidence-backed land intelligence system, ASTATINE defends against three critical threat vectors:
1. **Cadastral Tampering & Title Manipulation:** Malicious alteration of parcel boundaries, unit footprints, or floor registrations.
2. **Geospatial Injection & DoS Exploitation:** Submitting malicious Shapefiles, bloated GeoTIFFs, or poisoned GeoJSONs designed to trigger server memory exhaustion or buffer overflow in C-based GDAL/GEOS libraries.
3. **AI Injection & Prompt Escapes:** Exploiting the natural-language spatial interface to execute arbitrary database mutations or extract unredacted owner titles.

## 2. Core Security Guardrails & Countermeasures

```
                               SECURITY DEFENSE-IN-DEPTH
                                          │
            ┌─────────────────────────────┼─────────────────────────────┐
            ▼                             ▼                             ▼
   [PERIMETER & TRANSPORT]         [INPUT & GIS DEFENSE]         [AI & DATA LAYER]
   - TLS 1.3 Strict               - Strict MIME Validation       - Zero-Raw-SQL Pipeline
   - CORS Whitelist               - GDAL Memory Sandboxing       - Pydantic AST Validation
   - Token Rate Limiting          - Max File Size Enforced       - SHA-256 Audit Chaining
   - Content Security Policy      - Coordinate Range Sanity      - Subsurface Masking
```

### 2.1 Defense Against LLM Injection & Arbitrary SQL Execution
- **Vulnerability:** Unfiltered LLM queries could output:  
  `"Show all buildings; DROP TABLE parcels; --"`
- **Architecture Defense:**
  - The Gemini LLM has **zero direct connectivity** to the PostgreSQL database.
  - Output is strictly constrained to a Pydantic-enforced **Spatial Query AST JSON schema**.
  - If the LLM generates any raw SQL syntax (e.g., `SELECT`, `DROP`, `UNION`, `;`), the parser rejects the payload before reaching the database adapter.
  - The backend compiler constructs queries solely via SQLAlchemy Core with parameterized bind variables.

### 2.2 Geospatial File Ingestion & Spatial Sanitization
- **Vulnerability:** Malicious Shapefiles (ZIP bombs, corrupted DBF headers) or oversized GeoTIFFs triggering Denial of Service (DoS) in GDAL/Rasterio.
- **Architecture Defense:**
  - Maximum upload ceiling enforced: 250 MB for vector shapefiles, 1.5 GB for orthomosaics.
  - Ingestion runs in an isolated worker process with strict memory ceilings ($4\text{ GB RAM}$ limit via Linux cgroups/Docker limits).
  - Geometries are validated immediately upon ingestion using `ST_IsValid` and `ST_MakeValid`.
  - Coordinates are checked against realistic bounding envelopes ($\text{Lon} \in [68^\circ, 98^\circ], \text{Lat} \in [6^\circ, 38^\circ]$ for Indian territory).

### 2.3 Secrets Management & Zero-Leakage Guarantee
- **Frontend Hygiene:** The Next.js client bundle strictly isolates environment variables. No database credentials, S3 secret keys, or Gemini API keys are prefixed with `NEXT_PUBLIC_`.
- **Backend Key Storage:** Backend configuration loads secrets strictly from `.env` files via Pydantic `BaseSettings` or Docker Secrets.
- **Client Tile Gateways:** S3 / MinIO raster tiles and 3D tilesets are delivered via short-lived, presigned URLs ($15\text{ min}$ expiry) generated by backend endpoints, preventing unauthorized mass scraping of national 3D tiles.

### 2.4 Subsurface Infrastructure Masking
- In compliance with national defense and security guidelines, underground utility vectors (power transmission mains, high-pressure gas pipelines, secure fiber corridors) are flagged with sensitivity ratings.
- The `/api/v1/infrastructure` endpoints redact subsurface coordinate precision for `PUBLIC_USER` accounts and blur depth measurements within designated sensitive zones.

### 2.5 Tamper-Evident Audit Ledger (Cryptographic Chaining)
Every change to a parcel boundary, floor plate, or verification state creates an entry in `audit_logs`:
$$\text{Current Hash} = \text{SHA-256}(\text{Previous Hash} + \text{User ID} + \text{Action} + \text{Timestamp} + \text{Payload JSON})$$
Any retrospective alteration of database records invalidates the hash chain, immediately alerting the System Administrator during automated integrity audits.
