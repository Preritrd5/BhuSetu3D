## 1. Geospatial (GIS) Processing Pipeline

The GIS engine serves as the deterministic, mathematical spine of ASTATINE. It handles geometric sanitization, coordinate projections, 2D-to-3D volumetric extrusion, vertical floor slicing, and topological clash evaluation.

### 1.1 Python GIS Technology Stack
- **`Shapely 2.0` (GEOS wrapper):** High-performance C-based planar geometric operations (intersection, difference, buffering, polygon simplification).
- **`GeoPandas`:** Spatial dataframes for batch vector transformations, spatial joins, and shapefile/GeoJSON I/O.
- **`GDAL / OGR`:** Direct low-level vector drivers and raster format translations.
- **`Rasterio`:** DEM/DSM raster sampling, elevation extraction, and slope analysis.
- **`PyProj`:** High-precision geodetic conversions across national grids and local projected coordinate systems (e.g., EPSG:7755 - Indian Terrestrial Reference Frame to EPSG:4326).

```
   RAW VECTOR / RASTER DATA
   (Cadastral SHP / Drone GeoTIFF / DEM)
              │
              ▼
   [Ingestion & CRS Reprojection Engine]
   (PyProj reprojection -> EPSG:4326 + local UTM metric space)
              │
              ▼
   [Geometric Topological Sanitization]
   - ST_MakeValid (resolve self-intersections, bowties)
   - Ensure Counter-Clockwise (CCW) exterior winding order
   - Douglas-Peucker orthogonalized simplification
              │
              ▼
   [Elevation Sampling & 3D Extrusion Engine]
   - Rasterio extracts ground elevation $Z_{ground}$ from DEM
   - Building height $H$ extracted from DSM/photogrammetry
   - Polyhedral extrusion: $Z_{base} = Z_{ground}$, $Z_{roof} = Z_{ground} + H$
              │
              ▼
   [Vertical Floor & Unit Slicing Engine]
   - Building height sliced into $N$ vertical floor plates: $h_{floor} = H / N$
   - Floor plates subdivided into unit bounding polyhedra
   - Compute exact 3D centroid $(X_c, Y_c, Z_c)$ for 3D ULPIN
              │
              ▼
   [Deterministic Topological Conflict Engine]
   - ST_Difference(building, parcel) -> Footprint encroachment
   - ST_DWithin(building, utility, buffer) -> Safety setback clash
   - ST_Area comparison -> Area discrepancy
```

### 1.2 Mathematical Specifications for Vertical Slicing
For a building situated on ground elevation $Z_0$ with total height $H$ and floor count $N$:
1. **Floor Base Elevation:** $Z_{base}(k) = Z_0 + k \cdot h_{floor}$ where $k \in \{0, 1, \dots, N-1\}$.
2. **Floor Ceiling Elevation:** $Z_{ceiling}(k) = Z_0 + (k+1) \cdot h_{floor}$.
3. **Unit Centroid:** For unit $u$ on floor $k$ with footprint polygon $P_u$:
   $$X_c = \frac{1}{A} \iint_{P_u} x \, dx \, dy, \quad Y_c = \frac{1}{A} \iint_{P_u} y \, dx \, dy, \quad Z_c = Z_{base}(k) + \frac{h_{floor}}{2}$$
4. **3D ULPIN Geocode Generation:**
   $$\text{ULPIN-3D} = \text{ULPIN-2D} + \text{"-B"}\langle\text{BldIdx}\rangle + \text{"-F"}\langle k\rangle + \text{"-U"}\langle u\rangle$$

## 2. Deterministic Spatial Conflict Detection Rules

Every conflict generated by ASTATINE is mathematically calculated using GEOS/PostGIS predicates.

### 2.1 Building Footprint Encroachment
- **Calculation:**
  $$\text{Encroachment Geom} = \text{ST\_Difference}(\text{Building Footprint}, \text{Cadastral Parcel})$$
  $$\Delta_{\text{encroach}} = \text{ST\_Area}(\text{Encroachment Geom})$$
- **Trigger Rule:** If $\Delta_{\text{encroach}} > 0.5\text{ m}^2$ (to account for survey GPS tolerance), create `CONFLICT` of type `FOOTPRINT_ENCROACHMENT`.
- **Severity Scoring:**
  - $\Delta_{\text{encroach}} \le 2.0\text{ m}^2$: `LOW`
  - $2.0\text{ m}^2 < \Delta_{\text{encroach}} \le 10.0\text{ m}^2$: `MEDIUM`
  - $\Delta_{\text{encroach}} > 10.0\text{ m}^2$: `HIGH`

### 2.2 Height & Floor Count Deviation
- **Calculation:** $\Delta_{\text{floors}} = F_{\text{detected}} - F_{\text{sanctioned}}$
- **Trigger Rule:** If $\Delta_{\text{floors}} \ge 1$, create `CONFLICT` of type `UNAUTHORIZED_VERTICAL_EXTENSION`.

### 2.3 Subsurface Utility & Setback Proximity
- **Calculation:** $\text{Dist} = \text{ST\_Distance}(\text{Building Footprint}, \text{Infrastructure Geometry})$
- **Trigger Rule:** If $\text{Dist} < \text{Buffer}_{\text{statutory}}$, create `CONFLICT` of type `INFRASTRUCTURE_BUFFER_BREACH`.

## 3. AI Spatial Investigator & NL Query Engine

The AI Spatial Investigator enables non-technical officers to query complex 3D spatial relationships using natural language without writing SQL or GIS scripts.

### 3.1 Strict Security Guardrail: Zero Raw SQL Execution
Under no circumstances does the system permit the LLM to generate or execute raw SQL strings directly against PostgreSQL. The architecture enforces an intermediate **Validated Abstract Syntax Tree (AST)** pipeline.

```
                  USER NATURAL LANGUAGE PROMPT
           "Show high-rise buildings exceeding sanctioned
                  floors in Sector 4"
                          │
                          ▼
            [GOOGLE GEMINI 1.5 PRO / FLASH]
              (Structured Tool Calling)
                          │
                          ▼
             [SPATIAL QUERY INTENT (AST)]
               (Pydantic Schema JSON)
              {
                "target_entity": "BUILDING",
                "filters": [
                  { "field": "floors_detected", "op": "GT_FIELD", "target": "floors_sanctioned" },
                  { "field": "region_name", "op": "EQUALS", "value": "Sector 4" }
                ],
                "spatial_predicates": []
              }
                          │
                          ▼
             [BACKEND QUERY COMPILER & SANITIZER]
             - Validates fields against allowed schema whitelist
             - Injects tenant/city boundary parameters
             - Compiles to parameterized PostGIS SQL with bind variables
                          │
                          ▼
            [POSTGIS EXECUTOR (GeoAlchemy2)]
             - Runs safe query: SELECT * FROM buildings WHERE ...
             - Retrieves matching entities & 3D geometries
                          │
                          ▼
             [EVIDENCE & REASONING ENRICHER]
             - Gathers linked datasets, confidence scores & photos
             - Formulates structured governance response
                          │
                          ▼
           [CESIUM 3D HIGHLIGHT + INSPECTOR VIEW]
```

### 3.2 Spatial Query AST Schema (Pydantic Model)
```python
from pydantic import BaseModel, Field
from typing import List, Literal, Optional, Union

class FilterCondition(BaseModel):
    field: Literal[
        "recorded_area_sqm", "computed_area_sqm", 
        "building_height", "detected_floors", "sanctioned_floors",
        "ulpin_2d", "ulpin_3d", "land_use", "verification_status"
    ]
    operator: Literal["EQ", "NEQ", "GT", "GTE", "LT", "LTE", "GT_FIELD", "LT_FIELD"]
    value: Optional[Union[str, float, int]] = None
    target_field: Optional[str] = None

class SpatialPredicate(BaseModel):
    predicate_type: Literal[
        "WITHIN_REGION", "INTERSECTS_INFRASTRUCTURE", 
        "ENCROACHES_PARCEL", "WITHIN_DISTANCE_METERS"
    ]
    reference_id: Optional[str] = None
    distance_meters: Optional[float] = None

class SpatialQueryAST(BaseModel):
    target_entity: Literal["PARCEL", "BUILDING", "FLOOR", "UNIT", "CONFLICT"]
    filters: List[FilterCondition] = Field(default_factory=list)
    spatial_predicates: List[SpatialPredicate] = Field(default_factory=list)
    limit: int = Field(default=50, le=200)
```

## 4. Computer Vision Building Extraction Model Architecture

For phases involving automated extraction from drone/satellite orthomosaics:
1. **Model Architecture:** Encoder-Decoder segmentation network (U-Net with ResNet34/ResNet50 backbone or SAM-GIS aerial fine-tuned checkpoint).
2. **Input Tensor:** 4-band ortho imagery (Red, Green, Blue, Near-Infrared) or 3-band RGB at 5cm–15cm Ground Sampling Distance (GSD).
3. **Inference & Vectorization:**
   - Model produces probability mask $M \in [0, 1]^{H \times W}$.
   - Binary thresholding at $\tau = 0.65$.
   - Polygon contour extraction via OpenCV / GDAL contouring.
   - **Regularization:** Application of building orthogonalization algorithms (e.g., Douglas-Peucker with minimum bounding rectangle right-angle alignment) to produce crisp architectural polygon footprints.
4. **Confidence Computation:**
   $$\text{Confidence} = 0.5 \cdot \text{MeanProb}(\text{Mask}) + 0.3 \cdot \text{EdgeGradientSharpness} + 0.2 \cdot \text{OrthogonalFitMetric}$$
   Output confidence is strictly recorded under the `evidence` table as a `DERIVED` source type.
